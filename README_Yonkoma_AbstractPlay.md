# Yonkoma for Abstract Play

Yonkoma as a game for the Abstract Play game server (gameslib, TypeScript), built on October 29, 2026 against the `develop` branch of https://github.com/AbstractPlay/gameslib (commit e23cf03).  New games enter Abstract Play with the `experimental` flag, which means they appear on https://play.dev.abstractplay.com first and on the production site once the maintainers clear them.

## Files to put into the gameslib repository

The patch file holds everything as one commit.  Applied to the `develop` branch it changes these files:

New files:

- `src/games/yonkoma.ts` (the game)
- `test/games/yonkoma.test.ts` (16 Mocha tests)

Changed files (all regenerated by the repository's own scripts, except the changelog line):

- `CHANGELOG.md` (Yonkoma added to the experimental games line under `[Unreleased]`)
- `locales/en/apgames.json` and `locales/en/apresults.json` (the English strings, written by `npm run locale-en -- merge --write`)
- `locale-src/en/apresults/apresults-path-map.json`
- `locales/de/apgames.json`, `locales/fr/apgames.json`, `locales/it/apgames.json`, `locales/es-US/apgames.json` and the four matching `locale-src/<lang>/apgames.json` files (the game name seeded into the managed locales, also by the merge script)

If the AP maintainers prefer to take only the two source files, they can run `npm run locale-en -- merge --write` themselves and add the changelog line.  The two source files are included separately for that purpose.

## What the game does

- Boards 10x10 (default) and 12x12.  Red is player 1 and moves first: Red starts on a1 and the opposite corner, Blue on the other two corners.
- Move entry: click a checker, its legal destinations light up in green, click one of them.  Clicking the selected checker again deselects it, clicking the other checker switches to it.  Every rejected click gets a message that says which rule it broke (not on an open diagonal, the distance rule, square occupied, checker has no legal move).
- A player with no legal move has the turn skipped.  The game carries the `autopass` flag, so the site submits the skip by itself.
- Whoever completes a crosscut loses.  The four squares of the crosscut are outlined at the end, and the move log says "<player> completed a crosscut and loses the game." followed by the winner line.
- No pie rule, as in the app and the BGA version.  The `pie` flag can be added in one line if you want it.
- Default colours are the app's red #e65049 and blue #5c6fb7.  Players who have customized their colours on Abstract Play keep their own.

## The artwork

Abstract Play draws every board from a JSON description with a shared renderer, so the felt and wood textures of the app cannot be copied over: the renderer accepts no images, no filters and no gradients inside custom shapes.  Within those limits the board is built to look like the app:

- the same tan felt colours for the dark and light squares, in an oak frame carrying the coordinates, with a dark edge where the felt meets the frame (the frame is a solid oak colour, no grain);
- the checkers are custom glyphs: a flat cylinder with a shaded side, a lit top face with a mottled glaze, a rolled rim and a highlight along the top edge, in the player's colour;
- legal moves in green squares, the selected checker and the final crosscut outlined in gold;
- a "Plain board" display option gives the ordinary Abstract Play checkered board and flat pieces for anyone who prefers it.

The two PNG files are the actual renderer output: a selected checker with its legal moves, and the end of a game.

## Verification

- `npm run typecheck`: clean.
- ESLint on both files: clean.  Locale checks (`locale-en` check and strict key coverage, Weblate keys, game names, JSON format): clean.
- The 16 Yonkoma tests pass, and the full repository suite passes (2,442 tests; one Bricka test file in the repository currently carries a `describe.only`, which has to be excluded to run the rest).
- The rules were cross-checked against the exact engine of the Yonkoma app: 800 random games (400 on each board), 12,561 positions, identical legal-move sets in every position, identical crosscut verdicts, 457 skipped turns handled the same way, every game ending in a crosscut completed by the loser, never a position with both players stuck.
- The click path, the partial-move rendering, serialization and reloading of earlier positions were exercised in the same run.
- Every render JSON was validated against the renderer's schema by rendering it with the renderer itself (the pinned renderer build, compiled from its source).

## Getting it onto Abstract Play through a GitHub account

1. Sign in to GitHub (or create an account at https://github.com/signup).
2. Open https://github.com/AbstractPlay/gameslib and press **Fork**, then **Create fork**.  That makes a copy at https://github.com/<your-name>/gameslib.
3. Connect the GitHub account to Claude (claude.ai, Settings, Connectors, GitHub) and give it access to the fork.  Claude then pushes the `yonkoma` branch with the commit into the fork.
4. Open https://github.com/<your-name>/gameslib/pull/new/yonkoma, make sure the base is `AbstractPlay/gameslib` branch `develop`, and press **Create pull request**.

Without the connector, the patch can be applied by anyone with git: `git checkout develop && git am yonkoma_abstractplay.patch && git push`.  The Abstract Play developers also take files directly in the #dev-curious channel of their Discord server (https://discord.abstractplay.com), as happened with Clear Path.
